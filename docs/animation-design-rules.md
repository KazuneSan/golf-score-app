# ドリルアニメーション デザイングランドルール

ゲートドリルのアニメーション制作で得た学びを体系化したもの。今後のドリルアニメーション(stright / over / eyesclosed / metronome / onehand 等)を作るときは、まずこのドキュメントを読んで適用すること。

---

## 0. 現在のアーキテクチャ (v2 — 2026-05 移行)

旧 `CinematicGateScene` (Animated API + viewBox 320×260 + 後方視点) は廃止。
現在は次の構成:

| 役割 | ファイル |
|------|----------|
| 共有プリミティブ + テーマ + タイムライン | `src/components/drillPrimitives.js` |
| ゲートドリル固有のシーン | `src/components/GateDrillAnimation.js` |
| 仕様テンプレート (新ドリル設計用) | `docs/drill-template.md` |
| 視覚ルール (本ファイル) | `docs/animation-design-rules.md` |

### 0.1 必ず drillPrimitives から import する

```js
import {
  CANVAS_W, CANVAS_H, BALL_R, DEFAULT_THEME,
  easing, clamp, useDrillTimeline,
  GolfBallTopDown, GolfTee, MalletPutter,
  DimensionLabel, StreakHUD, CheckBadge, CaptionOverlay,
} from './drillPrimitives';
```

**`GateDrillAnimation` から import しない**(依存方向が逆になる)。

### 0.2 標準キャンバス (全ドリル共通)

- viewBox: `0 0 720 800` (CANVAS_W × CANVAS_H)
- ボール半径: `BALL_R = 38`
- 中心線: `CX = 360`
- ↑ を共有することで StreakHUD など W 依存プリミティブが drill 間でレイアウト崩れしない。

### 0.3 コンテナ aspectRatio は drill ごとに切替

`DrillDetailScreen.diagramBody` のデフォルトは `320/260` (横長)。
viewBox 720×800 (縦長) と aspect がズレると左右に余白が出る。
新ドリルを追加するときは必ず:

```jsx
<View style={[
  styles.diagramBody,
  drill.setup === '[name]' && { aspectRatio: 720 / 800 },
]}>
```

これを忘れた瞬間に「絵が小さい」という結果になる(ゲートドリル実例)。

### 0.4 タイムライン (useDrillTimeline)

旧: `Animated.Value` + `t.interpolate` の手書きキーフレーム配列
新: `requestAnimationFrame` ベースの `time` (秒) を派生計算で使う

```jsx
const { time, phase } = useDrillTimeline({
  duration: 11, autoPlay: true, loop: true, phaseOf, onPhase,
});

// time から各要素を派生
const ballEntry = clamp((time - 2.7) / 0.5, 0, 1);
const swing = (time >= T_IMPACT) ? ... : 0;
```

利点: タイムライン全体を一目で追える(キーフレーム配列の山にならない)。
ループ動作は `time % duration` で勝手に解決される。

### 0.5 新規プリミティブ追加ルール

- drill 固有ファイルに書かず、**drillPrimitives.js に追加**
- 視覚言語を守る: cream fill (`#fbf8ee`) + ink outline (`#1a1714`) + subtle ellipse shadow
- 1度書いたら他の drill でも使えるか自問する。Yes ならプリミティブに昇格

### 0.6 旧アーキへの注意

下記 8〜9 章の技術実装パターン (`Animated.createAnimatedComponent`、camScale 補間配列、teePath 文字列等) は **旧アーキ用**。現在は使わない。視覚設計の参考としてのみ残してある。

## 1. 最優先の原則(これを破ると全部やり直しになる)

### 1.1 ドリルの仕様を正確に理解してから絵を描く
- 何を、どこに、どの順番で配置するのか、何が**含まれない**のかをまず確認する
- 例: ゲートドリルにはカップ(ホール)は登場しない。ボールはゲートの**手前**にある
- 仕様確認なしに描き始めると、絵を5回直すことになる

### 1.2 初心者(非ゴルファー)視点でセルフレビューする
毎回コードを書いた後、以下を自問する:
- ✓ 各オブジェクトが**何か一目で分かる**か?(ティーが釘・きのこ・砂時計に見えていないか)
- ✓ ドリルの**目的が直感的に伝わる**か?(なぜこの配置なのか)
- ✓ **テキストを読み切れる時間**があるか?(日本語は8文字/秒で読める前提)
- ✓ アニメーションの**動き先が予測できる**か?(突然ジャンプしないか)

### 1.3 参照画像があるなら必ず使う
ユーザーが画像を渡した場合、その**シルエットの差分を厳密に分析**してから描く。
「だいたい合ってる」で済ませると違和感が残る。

## 2. ビジュアルスタイル(トンマナ)

### 2.1 配色(必須統一)
| 用途 | 色 | 備考 |
|------|-----|------|
| キャンバス背景 | `#F7F4ED` | ウォーム・オフホワイト。緑・グラデ・芝禁止 |
| メインインク(ティー、文字主役) | `#1F1F1E` | 純黒禁止、わずかに暖色 |
| サブテキスト | `#6B6B66` | キャプション、ラベル |
| 寸法線・補助線 | `#9A9A92` | 主役を邪魔しない |
| ボール | fill `#FAFAFA` / stroke `#1F1F1E` | 周囲とコントラスト |
| 成功緑 | `#4A8A5C` | チェックマーク等のみ |
| 影 | `#1F1F1E` opacity 0.18-0.22 | 楕円で表現 |

色は **アクセントとしてのみ** 使う。広い面積を彩色しない。

### 2.2 不要な装飾を削る
- ❌ 芝のグラデーション
- ❌ 飾りタイトル(例: 左上「GATE DRILL」)
- ❌ 大きな成功バッジが動きに被る
- ❌ 派手なアウトライン
- ✓ Apple/Notion 風の最小限装飾

### 2.3 タイポグラフィ
- メインキャプション(動画下バー): 13px / weight 500
- 上部主役ラベル(例「ギリギリ通る幅」): 14px / weight 700 / letterSpacing 1
- サブ仕様(例「ボール+2cm」): 9px / weight 500 / letterSpacing 0.4
- 寸法ラベル(例「10cm」): 9px / weight 500
- フォントは `FONT.sans` 主、技術ラベルは `FONT.mono`

## 3. 構図とカメラ

### 3.1 標準ストーリーボード(5ビート構成)
```
Beat 1 (~1.8s): ズームイン → 主要オブジェクト1の配置
Beat 2 (~1.8s): パン → 主要オブジェクト2の配置
Beat 3 (~1.8s): ズームアウト → 全景+ボール+寸法
Beat 4 (~4.8s): メインアクション(スイング等)
Beat 5 (~1.8s): 成功バッジ + ホールド
合計: ~12秒
```

### 3.2 カメラパス
- 各ビートは **75%静止 + 25%キュービック・イーズインアウト遷移**
- 数式: `y = 3x² − 2x³`、サンプル点 0.25/0.5/0.75 → 0.156/0.500/0.844
- カメラは**右にしか動かない**(逆走禁止、画面酔い防止)
- 重要シーンの直前は必ず大きめの dwell を取る

### 3.3 視点(POV)
- ゲートドリル: ボール真後ろ視点(プレイヤーが構える視点)
- 真上(top-down)は **ティーが認識できない** ので避ける
- 真横は ゲート幅が見えなくなる ので避ける
- 一貫した視点を全ビートで維持。ハードカットの視点切替は禁止

### 3.4 ズームレベル(目安)
- ズームイン(オブジェクト個別フォーカス): scale **4.0**
- ズームアウト(全景): scale **1.0**
- 軽いズーム(成功時): scale **1.04**

## 4. オブジェクト描画ルール

### 4.1 ゴルフティー(必須シルエット)
**Path定義(再利用):**
```js
const teePath = (cx) => `M ${cx - 4} 100 L ${cx + 4} 100 L ${cx + 4} 102 Q ${cx + 3} 105 ${cx + 2} 107 L ${cx + 1} 128 L ${cx} 130 L ${cx - 1} 128 L ${cx - 2} 107 Q ${cx - 3} 105 ${cx - 4} 102 L ${cx - 4} 100 Z`;
```
**特徴:**
- 全長 30 SVG ユニット
- 平らなキャップ(幅8) → Q曲線で滑らかに細くなる(角度急変禁止) → 長いシャフト(70%以上) → 鋭い先端
- fill `#1F1F1E` のソリッド・シルエット(アウトライン不要)
- **下1/4(7.5SVG)は地面に埋める**(ClipPath で y >= 130 を非表示)

**避けるべきアンチパターン:**
- ❌ 釘形状(細いステム+ヘッド)
- ❌ きのこ形状(ボウル+細い柄)
- ❌ 砂時計/つぼ形状(中間にネック+下部に膨らみ)
- ❌ 棒の上に板チョコが乗ってるような cap

### 4.2 ボール
- 半径 7 SVG ユニット(ビューボックス 320×260基準)
- fill `#FAFAFA`、stroke `#1F1F1E` strokeWidth 0.7
- 影: `<Ellipse>` cy+5, rx=半径, ry=1.8、opacity 0.18
- 動くときはモーション・ストリーク(点線)を後ろに

### 4.3 パター(ボール真後ろ視点専用)
- ヘッドのみ + 短いシャフトが画面外へ抜ける描画
- グリップは描かない(視点上カメラの後ろにあり画面に映らない)
- ヘッド: ピル形 36×8 (rx=4)、フェース面ハイライト + サイトライン
- シャフト: ヒール側(右利きなら左)から斜め上に伸ばし画面外へ
- スイング動作: アドレス → タメ(ゆっくり引く) → スナップ(速く打つ) → フォロースルー の4段階
- ❌ シャフト垂直 + 中央グリップ → 真上視点と矛盾するので禁止

### 4.4 地面の表現
- 地面は **点線の細いライン1本のみ**(`y=130`、stroke 0.5、opacity 0.18)
- 芝・土・グラデは使わない
- ティーが刺さる演出は ClipPath による「地面より下を非表示」で実現

## 5. アニメーション・モーション原則

### 5.1 ディズニーの12原則の遵守
- **アンティシペーション**: 動作の前にためを作る(パターを引く)
- **スナップ**: 主動作は素早く(インパクト 200ms 以内)
- **フォロースルー**: 動作の後に余韻(振り抜き)
- **イーズイン/イーズアウト**: 静止 → 動き → 静止 を滑らかに

### 5.2 ティー挿入(刺す)モーション
```
落下フェーズ(400ms): キュービック・イーズイン(重力加速)
  -18 → 0 (キャップが画面上から地面へ)
打ち込みフェーズ(300ms): リニア
  0 → +7.5 (1/4が地中に埋まる)
インパクト演出: 着地リング(半径3→14、opacity 0.78→0)
                + 横方向の振動(±0.6, ±0.5, ±0.3, 減衰)
```

### 5.3 タイミング絶対値
| 動作 | 絶対時間 | 備考 |
|------|---------|------|
| ティー落下 | 400-500ms | 速すぎず遅すぎず |
| 打ち込み | 300ms | 落下より遅い |
| パター・スナップ | 200ms | 速い |
| パター・タメ | 800ms | ゆっくり |
| バッジ・フェードイン | 600-800ms | 焦らせない |
| キャプション・フェード | 180ms out / 280ms in | 自然な切替 |

### 5.4 キャプション読書時間
- 日本語: **8文字/秒** で読める前提
- 1ビート最低 **1.5秒** (短いキャプションでも)
- 14文字なら 1.75秒以上必要

## 6. レイアウト・ラベリング

### 6.1 メインキャプション(動画下のダークバー)
- 各ビートの **動作内容**(命令形が多い)
- ビート開始時にフェードイン、次のビートでフェードアウト

### 6.2 上部余白の活用
**重要なメッセージは上の余白に大きく置く**(動きに被せない)
- 上部 y=40-100 が定位置
- 矢印ブラケット + 点線コネクタで該当箇所を指す
- サブ仕様(例: 「ボール+2cm」)を主ラベルの上に小さく添える

### 6.3 寸法・距離ラベル
- 細い灰色の線(`#9A9A92` strokeWidth 0.5)
- 両端に短いティック
- ラベルは線の外側に配置

### 6.4 成功バッジ
- 上部余白に水平ピル形状で表示
- 動きに被らないこと(画面中央禁止)
- 動きより**ゆっくり**フェード(800ms)
- 「✓ ○○回連続でクリア」など意味そのものを書く(「5/5」だけは不親切)

## 7. セットアップビュー(静的説明図)

### 7.1 アニメーションと完全に同じビジュアル言語を使う
- 同じ背景色、同じシルエット、同じ位置、同じ色
- ティーは1/4埋没状態(アニメ最終状態)で静的描画
- 動きの代わりに **ラベル**(ボール、ギリギリ通る幅、10cm 等)を追加

### 7.2 セットアップビュー専用要素
- 「ボール」テキストラベル
- 「俯瞰ビュー」では映らない説明テキスト
- 寸法線は最初から表示

## 8. 技術実装パターン

### 8.1 必要な react-native-svg インポート
```js
import Svg, { Path, Rect, Circle, Ellipse, Line, Text as SvgText, G, Polygon, LinearGradient, Defs, Stop, ClipPath } from 'react-native-svg';

const AnimatedCircle = Animated.createAnimatedComponent(Circle);
const AnimatedEllipse = Animated.createAnimatedComponent(Ellipse);
const AnimatedG = Animated.createAnimatedComponent(G);
const AnimatedLine = Animated.createAnimatedComponent(Line);
const AnimatedRect = Animated.createAnimatedComponent(Rect);
```

### 8.2 標準アニメーションのアーキテクチャ
- マスタータイムライン `t` (Animated.Value 0→1) を1つだけ持つ
- 各要素のアニメーションは `t.interpolate(...)` で派生させる
- 全要素が同じタイムラインに同期される

### 8.3 カメラ・トランスフォーム
```js
const camScale = ...; // scale (1.0 to 4.0)
const camTxSvg = ...; // translateX
const camTySvg = ...; // translateY
// formula: tx = -scale * (focusX - 160); ty = -scale * (focusY - 130)
```

### 8.4 ClipPath による地中マスク
```jsx
<Defs>
  <ClipPath id="aboveGround">
    <Rect x={0} y={0} width={320} height={130} />
  </ClipPath>
</Defs>

<G clipPath="url(#aboveGround)">
  <AnimatedG y={teeDropY}>
    <Path d={teePath(cx)} fill="#1F1F1E" />
  </AnimatedG>
</G>
```

### 8.5 ループ・フェード
- 開始時 0.020, 終了時 0.97 で全体をフェード
- ループの境界が滑らかに繋がる

## 9. 開発フロー(チェックリスト)

新しいドリル・アニメーションを作るときは以下の順で進める:

1. ☐ ドリル仕様を確認(ゲート/カップ/ボール/距離など)
2. ☐ 既存の「ゲートドリル」アニメと**視覚言語を統一する**
3. ☐ 5ビートのストーリーボードを書く(各ビート=何を伝えるか)
4. ☐ 各ビートに最低1.5秒、合計約12秒で設計
5. ☐ 主要オブジェクトのシルエットを参照画像と比較しながら描く
6. ☐ アンティシペーション・スナップ・フォロースルーをモーションに入れる
7. ☐ 最初の実装後、**初心者視点でセルフレビュー**(8つの質問を自問)
8. ☐ セットアップビューもアニメと同じトンマナで作る
9. ☐ ループ・フェード・キャプション・成功バッジを忘れずに

## 10. 反復で得た特に重要な失敗パターン

過去のミスから学ぶ。下記を避けるだけで質が大きく変わる:

| 失敗 | 教訓 |
|------|------|
| カップを描いてしまった | ドリル仕様を毎回確認 |
| ティーが釘/きのこ/砂時計に見えた | 参照画像と差分を厳密に比較 |
| キャプションが1秒で切り替わった | 最低1.5秒・8文字/秒前提 |
| 成功バッジが動きに被った | 主役エリアを避ける、上部余白に置く |
| グリップを描いて視点が破綻 | 真後ろ視点ならグリップは画面外 |
| ティーが地面に乗ってるだけ | ClipPath で1/4埋める |
| 設定図(セットアップ)が古いまま | アニメ刷新時にセットアップも同期 |
| アニメの遷移がフラット(等速) | 75%静止+25%イーズで緩急つける |
| ティー挿入が「ねっとり」遅い | スナップは絶対時間で固定(400ms) |
| 寸法ラベルが小さくて読めない | 上部余白に大きく + 矢印で指す |

---

このドキュメントは、新しいドリル・アニメーションを設計する **前** に必ず参照すること。実装後の修正コストは設計時の意思決定の何倍にもなる。
